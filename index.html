PLAYBOOK 01・觀念與診斷

為什麼有官網，AI 還是找不到你？

一句話結論：因為 AI 不是把整頁網站看完再推薦你，而是「先決定要不要連網檢索 → 挑選抓得到且可信的網址 → 只切出最像標準答案的那一段文字」。只要四層依賴（訪問 → 定向 → 理解 → 可引用）斷在任何一層，官網做得再漂亮，在 AI 眼裡都等於不存在。

一、先搞懂 AI 推薦你的「三段漏斗」

傳統 SEO 的終點是「十條藍色連結」裡的點擊；GEO 的終點則是「AI 答案裡有沒有提到你的名字，而且把價格、流程、聯絡方式說對」。使用者提出問題後，引擎會經過三道關卡：第一關看這個問題需不需要連網查資料；第二關由搜尋索引與爬蟲決定哪些網站能進候選清單；第三關才把抓回來的網頁切塊，挑出最對題、證據最紮實的段落寫進最終答案。因此，GEO 的最小單位不是「一個網站」，而是「一段可以單獨拿來當證據的文字」。

二、實戰中最常見的 4 個致命地雷

  • 地雷 1：爬蟲根本抓不到（SPA 空殼或防火牆誤殺）——許多新潮官網全部靠前端 JavaScript 動態載入文字，瀏覽器打開看得到，但多數 AI 檢索爬蟲（如 OAI-SearchBot、ChatGPT-User、Claude-SearchBot、PerplexityBot、DeepSeekBot）只抓靜態 HTML，結果抓到一片空白；或者 robots.txt 寫了開放，CDN 防火牆卻偷偷對 AI 爬蟲回傳 403。
  • 地雷 2：把最重要的價格與方案做在圖片裡——不少品牌把價目表、流程圖做成精美 PNG 或海報，卻沒有對應的純文字 HTML 表格。爬蟲看不到清楚數字，回答時不是跳過你，就是胡亂猜一個過期價格。
  • 地雷 3：舊測試站與外部舊文案還在線上打架——這是 cccnan.art 實測中踩過最痛的坑。即使正式官網已經更新，只要早年的 Vercel 測試網址、舊 Notion 頁或舊粉專簡介還沒清理，AI 仍會把舊價、舊流程拼進回答裡，甚至把同名品牌認成別縣市的店家。
  • 地雷 4：全篇都是抒情形容詞，沒有「可抽取事實」——像「業界領先、用心傾聽、質感滿分」這類空話，AI 無法拿來回答使用者的決策問題。實證研究指出，頁面包含具體數字（引用影響力 +61.6%）、一句話定義（+57.3%）、對比表（+55.3%）與步驟（+41.2%），遠比感性口號更容易被吸收。

三、動手修之前，照「四層依賴順序」排先後

不要一上來就狂寫部落格或堆關鍵字。GeoLook 的四層依賴原則很直白：先檢查「訪問層」（HTTP 200、靜態 HTML 正文、robots 與防火牆不擋爬蟲）→ 再檢查「定向層」（sitemap、canonical、有效 llms.txt）→ 接著補「理解層」（JSON-LD 結構化資料與品牌別名一致）→ 最後才打磨「可引用層」（首段倒金字塔結論、真實價格規格表、服務邊界與外部提及）。上面一層沒打通，下面做再多都是白工。

PLAYBOOK 03・技術落地與範本

llms.txt、Schema 與問答結構化怎麼寫？

一句話結論：把官網改造成 AI 讀得最順的「證據頁」，核心就是三件套：讓爬蟲暢通（robots.txt）、給一份 5～8 頁精簡目錄（llms.txt），以及讓可見文字與 JSON-LD Schema 一一對應。下面直接附上可照抄改寫的最小可用範本。

一、先確認 robots.txt 區分「AI 搜尋爬蟲」與「模型訓練爬蟲」

在寫任何進階檔案前，先打開你網站根目錄的 /robots.txt，把爬蟲分成兩群：搜尋與即時問答爬蟲（如 OAI-SearchBot、ChatGPT-User、Claude-SearchBot、Claude-User、PerplexityBot、DeepSeekBot、Googlebot、Bingbot）必須明確 Allow: /；而基礎模型訓練爬蟲（如 GPTBot、ClaudeBot、Applebot-Extended、CCBot、Amazonbot）則依你的內容版權策略決定是否 Disallow: /（本公開站即採「鎖死訓練、開放搜尋」原則）。記住：放行後還要確認 CDN 或防火牆沒有對搜尋爬蟲回傳 403。

二、/llms.txt 怎麼寫？精簡 5～8 個核心頁就夠

llms.txt 就像遞給大型語言模型的「一頁式品牌名片＋導覽目錄」。千萬不要把整站幾百篇文章全部塞進去，也不要放會回傳 404 的失效連結。標準寫法只要四段：一句話品牌身分、固定價格與流程事實、明確服務邊界（不做的事）、5～8 個最核心的正式網址與官方聯絡入口： 

# 你的品牌名稱｜創辦人或核心定位
> 一句話說明你是誰、服務哪類對象、全程線上或服務地區。

## 核心服務與公開價格
- 方案 A（入門名稱）：NT$X,XXX｜交付天數｜包含項目
- 方案 B（主推名稱）：NT$X,XXX｜交付天數｜包含項目

## 服務流程與不承接範圍
- 流程：先以文字確認需求 → 報價確認 → 開始製作 → 驗收交付
- 不承接：清楚列出不做的項目（寫清邊界反而提升 AI 信任度）

## 核心頁面（只列 5～8 頁，每頁須回傳 HTTP 200）
- [服務方案與價目](https://example.com/work/): 完整方案對比表與常見問答
- [代表案例與實績](https://example.com/cases/): 去敏實測紀錄與交付範例

## 官方聯絡入口
- 官方 LINE：@your_id

三、JSON-LD Schema（@graph）與問答結構化（Citation Bait）

Schema 的重點不是塞越多標籤越好，而是用 @id 與 @graph 把「品牌／創辦人（Organization 或 Person）→ 服務與報價（Service＋Offer）→ 常見問答（FAQPage）」串成一張機器讀得懂的關係圖，而且JSON-LD 裡的每一個價格、名稱與問答，都必須與網頁上訪客肉眼看得到的純文字完全一致。

  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Person",
      "@id": "https://example.com/#brand",
      "name": "品牌全稱｜負責人",
      "alternateName": ["簡稱", "粉專別名"],
      "sameAs": ["https://www.youtube.com/@yourchannel"]
    },
    {
      "@type": "Service",
      "name": "主力服務名稱",
      "provider": { "@id": "https://example.com/#brand" },
      "offers": { "@type": "Offer", "price": "3800", "priceCurrency": "TWD" }
    },
    {
      "@type": "FAQPage",
      "mainEntity": [{
        "@type": "Question",
        "name": "做一次 GEO 健檢大概需要多久、會拿到什麼？",
        "acceptedAnswer": {
          "@type": "Answer",
          "text": "約 5 個工作天完成，交付 20 題跨引擎原始問答證據表與 6 維站點改善優先清單。"
        }
      }]
    }
  ]
}

最後提醒一個實測反常識的細節：只把文章排成「Q&A 格式」本身不會加分（實證甚至略降 5.7%）；真正讓段落成為「Citation Bait（高引用誘餌）」的寫法，是用用戶真實會問的問句當小標，在段落前 2～3 句（約 150 字內）用倒金字塔直接給答案，接著補上具體數字、HTML 對比表格與操作步驟。這樣不論是搜尋引擎還是 AI 檢索器，都能一秒把你的段落整塊引走。

CASE STUDY 04・AI 報錯舊價破案實錄

AI 報錯舊價破案實錄：為什麼官網改價了，AI 還是把舊規則背出來？

一句話結論：AI 會背出舊價格與舊流程，幾乎不是它憑空捏造，而是因為網路上還留著「搜尋引擎舊快照、忘記關的舊測試網址、站外未同步的公開筆記」這三個影子分身。只改正式官網卻不追查舊分身，就像換了新菜單卻把舊菜單繼續貼在後門一樣。

一、第一現場：明明改版了，AI 卻一字不差背出舊流程

在 cccnan.art 的 1,298 筆實測過程中，最讓人頭痛的一次狀況發生在 10 月下旬到 11 月中：當時正式官網早已公布四個固定公開方案（主推 B NT$6,800、A NT$4,800、C NT$3,500、D NT$9,000），流程也明確改成「先用文字傳故事，寫故事這步不收費」。但我們用全新無痕對話測試 ChatGPT 的品牌直問題（Q03～Q05）時，它卻一再回答：「先聊 30～45 分鐘訪談、交期 1～10 天、費用依需求報價、會附手寫故事卡」。

二、我們怎麼四步抓出錯誤來源？

  • 第一步：先驗證「現在的正式官網」到底有沒有寫錯——用腳本一次抓回全站所有公開頁面的 HTML、Meta 描述與 JSON-LD，確認正式站正文與結構化資料 100% 是新版，完全沒有那些舊詞彙。這一步排除了「自己漏改某個內頁」的可能。
  • 第二步：回翻程式改版歷史，做逐字比對——把 AI 答出來的「約 30–45 分鐘訪談」「交期 1～10 天」「依需求報價」「故事卡」，拿去對照更早以前（2026-10-09 改版前）的接案頁舊程式碼。結果在第 27 行、第 32 行與第 78 行的舊表格裡，找到一模一樣的原句。這證明 AI 不是亂編，而是讀到了某一版歷史留影。
  • 第三步：沿著引文網址，抓出三個「影子分身」——繼續比對搜尋引擎收錄紀錄與站外公開頁，共找出三個元兇：① 搜尋引擎尚未重新抓取的 /work/ 舊索引快照（顯示數週前的舊標題）；② 早年上線測試後忘記關閉的兩個舊預覽網址，依然回傳 HTTP 200 且允許收錄舊價；③ 早年公開的外部筆記頁與舊社群簡介，整頁還停在舊流程。
  • 第四步：避開「否定句過度重複舊詞」的陷阱——起初為了澄清，我們在官網 FAQ 裡反覆寫「沒有 30～45 分鐘訪談」，結果發現過度重複舊關鍵字反而容易在摘要擷取時被斷章取義；後來改為「正面直寫現行做法（用 LINE 文字傳故事，不收費）」，只在必要處保留一條明確的邊界說明。

迷思 01｜短期奇蹟話術

「只要 72 小時就能讓 AI 必收錄、穩排第一名？」

實戰真相：AI 回答帶有隨機性，加上各搜尋索引換版週期不同，沒有人能鎖定特定排名。正規做法是先清理舊源與補齊結構，再以 8～12 週同條件實測看趨勢，不買口頭承諾。

迷思 02｜單一檔案迷信

「網站放了 llms.txt 就一定被推薦，沒放就完全抓不到？」

實戰真相：llms.txt 是給大型模型看的精簡目錄，屬於加分導覽而非萬靈丹。真正決定 AI 找不找得到你、會不會報對價格的，仍是靜態 HTML 可讀取性、乾淨索引與純文字對比表。

迷思 03｜自嗨假分數與灌水洗版

「工具跑出 90 分，或把同一篇文章發六個自家帳號就等於背書？」

實戰真相：模擬器測爬蟲回傳 200 不等於真實 AI 搜尋已引用；同一篇自我介紹貼六個自家帳號也不會變成六個獨立背書。只有「無痕新對話、不餵答案」的實測原答與第三方真實提及才算數。

迷思 04｜黑帽紅線

「在網頁角落塞白底白字或提示詞注入，叫 AI 一定要誇我？」

實戰真相：隱藏文字與提示詞注入不只違反搜尋規範，還會觸發 AI 安全過濾甚至整站被降權。我們絕不塞隱藏提示詞、絕不買垃圾外鏈農場，只做訪客與機器讀到完全一致的透明事實。
